# Alex'step: подготовка Android-оболочки и APK

## Что уже готово

- `public/manifest.webmanifest`: название, русский язык, запуск с `/`, область `/`, отдельное окно и иконки.
- `public/icons/icon-192.png` и `icon-512.png`: обычные иконки.
- `public/icons/icon-maskable-512.png`: иконка с безопасным полем для обрезки Android.
- `public/icons/apple-touch-icon.png`: 180 × 180; `public/favicon.png`: 64 × 64.

**APK пока не собран.** Ниже — отдельный проект оболочки на Capacitor 7 для проверки на телефоне. Он открывает опубликованный HTTPS-сайт; интернет нужен для запуска. Service worker и офлайн-кэш не добавлены. Манифест сам по себе не гарантирует предложение установки во всех браузерах.

## 1. Опубликуйте сайт

В Lovable нажмите «Publish» и откройте публичный адрес на телефоне. Предполагаемый адрес проекта:

`https://shagalka-daily-step-companion.lovable.app`

На момент подготовки приложение не опубликовано: сначала проверьте адрес после публикации. Не используйте адрес предпросмотра `id-preview--…`. Проверьте страницы Сегодня, История и Настройки, доступность `/manifest.webmanifest` и `/icons/icon-512.png`.

## 2. Установите инструменты на компьютер

Нужны Node.js 22 LTS, Android Studio, Android SDK Platform 35 и JDK 21 (встроенный в подходящую версию Android Studio). В SDK Manager установите SDK Platform 35, Build Tools и Platform Tools. Инструкции рассчитаны на **Capacitor 7**, а не автоматически на любую будущую версию.

## 3. Создайте отдельную папку оболочки

Не выполняйте эти команды внутри исходного проекта Lovable:

```sh
mkdir alex-step-android
cd alex-step-android
npm init -y
npm install @capacitor/core@7 @capacitor/android@7
npm install --save-dev @capacitor/cli@7 @capacitor/assets@3
mkdir www
mkdir assets
```

Сохраните в `www/index.html` минимальную запасную страницу:

```html
<!doctype html>
<html lang="ru">
<head><meta charset="utf-8"><meta name="viewport" content="width=device-width, initial-scale=1"><title>Alex'step</title></head>
<body><h1>Alex'step</h1><p>Для загрузки приложения необходимо подключение к интернету.</p></body>
</html>
```

Она нужна как локальная папка webDir; **при недоступности сайта автоматический переход на неё не гарантируется**. Для полноценной обработки отсутствия сети нужен отдельный экран оболочки.

## 4. Настройте оболочку

В корне новой папки создайте `capacitor.config.json`:

```json
{
  "appId": "com.alexsychev.alexstep",
  "appName": "Alex'step",
  "webDir": "www",
  "server": {
    "url": "https://shagalka-daily-step-companion.lovable.app",
    "cleartext": false
  }
}
```

Замените URL, если адрес после публикации другой. `appId` — предложенный идентификатор: выберите свой уникальный до первого выпуска и не меняйте его при обновлениях.

**Важно:** `server.url` у Capacitor прежде всего предназначен для разработки/live reload. Здесь он используется для тестовой онлайн-оболочки, а не как рекомендация для выпуска в Google Play. Любое обновление сайта меняет содержимое оболочки. Не подключайте привилегированные нативные плагины к недоверенному удалённому содержимому; для выпуска потребуется отдельная проверка безопасности и требований магазина.

Текущий проект использует TanStack Start с серверным рендерингом. Нельзя просто скопировать `dist` или `.output` в `www`: это не гарантированно автономный статический сайт. Полноценная офлайн-упаковка потребует отдельной клиентской сборки и адаптации запуска.

## 5. Добавьте Android и значок

```sh
npx cap add android
```

Скопируйте `public/icons/icon-512.png` из веб-проекта в `assets/icon-only.png` новой папки, затем выполните:

```sh
npx capacitor-assets generate --android
npx cap sync android
npx cap open android
```

Проверьте результат иконок в Android Studio. Генератор берёт изображение из `assets`, а не иконку из веб-манифеста.

## 6. GPS и разрешения

В `android/app/src/main/AndroidManifest.xml` перед `<application>` убедитесь, что есть:

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
```

Не дублируйте уже существующие записи. Не добавляйте доступ к геолокации в фоне: текущая версия не поддерживает фоновые прогулки.

Записей в манифесте **недостаточно**: нужно разрешение Android во время работы и поддержка запроса геолокации WebView. Сначала проверьте текущий `navigator.geolocation` на настоящем телефоне. Если запроса нет или GPS не работает, потребуется подключить `@capacitor/geolocation@7` и адаптировать запуск/остановку прогулки в приложении (requestPermissions, watchPosition, clearWatch) либо правильно обработать запросы WebView в оболочке. Установка плагина сама по себе не заменяет браузерный вызов. Эта адаптация в текущую подготовку не входит.

`DeviceMotionEvent` в Android WebView может отсутствовать даже при исправном акселерометре. Оболочка не превращает браузерный алгоритм в системный шагомер. Для проверки без датчика есть ручное добавление и отдельный демо-режим.

## 7. Соберите тестовый APK

В Android Studio дождитесь Gradle Sync. Подключите Android-телефон с включёнными параметрами разработчика и отладкой USB, выберите устройство и нажмите Run.

Для файла APK откройте меню Build и действие Generate/Build APKs (название зависит от версии Android Studio). Альтернатива из папки `android`:

```sh
# macOS / Linux
./gradlew assembleDebug

# Windows
gradlew.bat assembleDebug
```

Результат: `android/app/build/outputs/apk/debug/app-debug.apk`. Этот APK подписан отладочным ключом и подходит для тестирования, не для публикации. Передайте его на телефон и разрешите установку из выбранного источника, если Android попросит. Не отключайте системную защиту целиком.

## 8. Выпуск с постоянной подписью

В Android Studio выберите Build → Generate Signed App Bundle / APK → APK. Создайте keystore, сохраните его и пароли в безопасном месте вне репозитория. Выберите release и запомните путь из сообщения о завершении сборки.

Для обновлений сохраняйте тот же appId и ключ подписи, увеличивайте `versionCode` и меняйте `versionName` в `android/app/build.gradle`. Debug-версию обычно придётся удалить перед установкой release из-за разных подписей — это удалит её локальные данные. Для Google Play обычно нужен AAB и соответствие актуальным требованиям, а не просто APK; SDK 35 здесь выбран для совместимости с Capacitor 7, не как гарантия требований магазина на дату выпуска.

## 9. Проверка на реальном телефоне

- Приложение открывается после установки, название и значок правильные.
- Все четыре вкладки открываются, кнопка Android «Назад» работает ожидаемо.
- Ручное добавление шагов и настройки сохраняются после закрытия и повторного запуска.
- Демо-данные не смешиваются с реальными.
- GPS корректно обрабатывает разрешение, отказ, начало и остановку прогулки.
- Датчик проверяется отдельно; отсутствие DeviceMotion в WebView считается ограничением, не доказательством работы шагомера.
- При выключенном экране и в фоне **не ожидается надёжного подсчёта**.
- Запуск без сети проверяется отдельно; текущая онлайн-оболочка не обещает работу офлайн.

Данные сайта в Chrome не переносятся автоматически в WebView: APK начинает с отдельного хранилища. Удаление приложения удаляет его локальные данные. Координаты кодом Alex'step не загружаются на сервер, но онлайн-оболочка скачивает сайт через интернет.

## Следующий этап для полноценного Android-шагомера

Нативный мост к `Sensor.TYPE_STEP_COUNTER`, проверка доступности аппаратного датчика, разрешение `ACTIVITY_RECOGNITION` на Android 10+, стратегия сохранения и фоновой работы с учётом ограничений Android. APK-оболочка сама этого не добавляет.
